32  Time Series

Processing date and time information in Python is enabled through various modules. A brief introduction to some of these modules is given, as they are occasionally referenced in the documentation. Pandas provides a unified access to most of these functions and uses the NumPy data types datetime64 and timedelta64.

  • The data type datetime64 represents a specific point in time on a specific date and belongs to the Timestamp class. The data type has nanosecond precision and can store timezone information.

  • The data type timedelta64 represents an absolute duration of time in nanoseconds and belongs to the Timedelta class.

32.1 Date and Time Information in Python

In Python, there are several modules for handling date and time information.

  • The time module provides time and date operations with objects of type struct_time. (time module documentation)

  • The datetime module introduces the data types datetime and timedelta, along with additional methods for processing and outputting date and time information. The module can handle years from 1 to 9999 in the Gregorian calendar. (datetime module documentation)

  • The calendar module provides various calendar functions and extends the range of dates that can be processed. Based on the Gregorian calendar, this extends infinitely in both directions. (calendar module documentation)

  • The pytz module provides the IANA timezone database (Internet Assigned Numbers Authority, also called the Olsen database) for applications and operating systems. The IANA database includes time zones and changes since 1970. (Wikipedia) The pytz module ensures correct calculation of times at the end of daylight saving time across time zones. (pytz documentation)

  • NumPy introduces the data types datetime64 and timedelta64. These are based on the Gregorian calendar and extend infinitely in both directions. https://numpy.org/doc/stable/reference/arrays.datetime.html

  • Pandas uses the NumPy data types datetime64 and timedelta64 and adds many functions for processing date and time information from other packages. https://pandas.pydata.org/docs/user_guide/timeseries.html

NumPy and Pandas can convert datetime objects from other modules into the datetime64 data type.

32.1.1 Naive and Aware Datetime Objects

Datetime objects are classified as naive or aware depending on whether they contain timezone information. Naive datetime objects lack this information, while aware datetime objects include it. Objects from the time, datetime, and Pandas modules have a timezone attribute, so they are aware. np.datetime64 has been a naive data type since NumPy version 1.11.0 but still supports timezones for backward compatibility.

 

“Deprecated since version 1.11.0: NumPy does not store timezone information. For backwards compatibility, datetime64 still parses timezone offsets, which it handles by converting to UTC±00:00 (Zulu time). This behaviour is deprecated and will raise an error in the future.” NumPy Documentation

32.1.2 Everything is Relative: The Epoch

Python stores time relative to a reference point, the Unix time, known as the epoch. The epoch can be displayed using the function pd.to_datetime(0). This function converts arguments into timestamps. Integers are interpreted as nanoseconds since the epoch. We will cover this function in more detail later.

import pandas as pd
print(pd.to_datetime(0))
1970-01-01 00:00:00
Warning 32.1: Time – Atomic, Coordinated, or Universal?

NumPy uses International Atomic Time (abbreviated TAI for French Temps Atomique International). TAI assumes each calendar day is exactly 86,400 seconds long, so it does not account for leap seconds. Atomic time forms the basis for Coordinated Universal Time (UTC).

UTC stands for Coordinated Universal Time (also known as Greenwich Mean Time). The abbreviation UTC is a compromise between English and French. Coordinated Universal Time compensates for the slowing of Earth’s rotation (astronomically measured as Universal Time, UT) with leap seconds to account for the slight lengthening of a day. TAI is therefore ahead of UTC. Since 1972, the difference between TAI and UTC is an integer number of seconds. Currently (2024), TAI is 37 seconds ahead of UTC.

A conversion to Coordinated Universal Time is not yet implemented in NumPy. (NumPy documentation, Wikipedia).

32.1.3 Daylight Saving Time

 

“DST is Daylight Saving Time, an adjustment of the timezone by (usually) one hour during part of the year. DST rules are magic (determined by local law) and can change from year to year. The C library has a table containing the local rules (often it is read from a system file for flexibility) and is the only source of True Wisdom in this respect.” (time module documentation)

 

 

Pandas works with Coordinated Universal Time (UTC) by default. UTC itself is not a timezone and therefore does not observe daylight saving time. Daylight saving is applied depending on the timezone. For example, Turkey abolished daylight saving in 2016 (and permanently adopted summer time).

In the following examples, a 24-hour time delta is added at 9 AM on the day before the DST change. Since the clock moves forward one hour during the night (morning of the next day), the resulting timestamp shows 10 AM if DST is in effect.

print("No daylight saving in UTC:")
print(pd.Timestamp("2025-03-29T09:00") + pd.Timedelta(24, "h"), "\n")

print("Timezone with daylight saving:")
print(pd.Timestamp("2025-03-29T09:00", tz="Europe/Berlin") + pd.Timedelta(24, "h"), "\n")

print("No daylight saving in Turkey today:")
print(pd.Timestamp("2025-03-29T09:00", tz="Turkey") + pd.Timedelta(24, "h"), "\n")

print("Turkey before abolishing daylight saving:")
print(pd.Timestamp("2014-03-30T09:00", tz="Turkey")  + pd.Timedelta(24, "h"))

32.1.4 Calendar

The calendar, NumPy, and Pandas modules use the Gregorian calendar extended backward before its introduction in 1582, known as the proleptic Gregorian calendar. While the date module only supports years 1–9999 CE, the datetime64 data type can also handle years before the Common Era using astronomical year numbering. This means there is a year 0 (the first year before CE), and preceding years are represented with negative numbers (-1 is the second year BCE). NumPy Documentation

32.2 datetime in Pandas

Pandas uses the NumPy data type datetime64 to process date and time information. In Pandas, datetime64 objects are created using the functions pd.to_datetime() or pd.date_range().
Note: Another option is the pd.Timestamp() function, which provides more extensive options for creating a timestamp but does not support string parsing.

pd.to_datetime() generates values of type datetime64[ns] (scalars created with pd.to_datetime() are returned as Timestamp objects, which do not have a dtype attribute). The function accepts the following inputs:

  • datetime objects from other modules.

  • Numbers and a time unit pd.to_datetime(1, unit=None) (default is nanoseconds). The unit argument accepts ‘ns’, ‘ms’, ‘s’, ‘m’, ‘h’, ‘D’, ‘W’, ‘M’, ‘Y’ for nanosecond, millisecond, second, minute, hour, day, week, month, or year. The result is a timestamp relative to the epoch.

print(pd.to_datetime(1000, unit = 'D'))
print(pd.to_datetime(1000 * 1000, unit = 'h'))
print(pd.to_datetime(1000 * 1000 * 1000, unit = 's'))
1972-09-27 00:00:00
2084-01-29 16:00:00
2001-09-09 01:46:40
  • Strings representing a date or a date with time, formatted according to ISO 8601.
print(pd.to_datetime('2017'))
print(pd.to_datetime('2017-01-01T00'))
print(pd.to_datetime('2017-01-01 00:00:00'))
2017-01-01 00:00:00
2017-01-01 00:00:00
2017-01-01 00:00:00
  • Strings in other formats using the argument format = "%d/%m/%Y" (see strftime documentation for string formatting).
print(pd.to_datetime('Monday, 12. August `24', format = "%A, %d. %B `%y"))
print(pd.to_datetime('Monday, 12. August 2024, 12:15 Uhr CET', format = "%A, %d. %B %Y, %H:%M Uhr %Z"))
2024-08-12 00:00:00
2024-08-12 12:15:00+02:00
  • Dictionary or DataFrame.
print(pd.to_datetime({'year':[2020, 2024], 'month': [1, 11], 'day': [1, 21]}), "\n")
print(pd.to_datetime(pd.DataFrame({'year':[2020, 2024], 'month': [1, 11], 'day': [1, 21]})))

The function pd.date_range() generates an array of type DatetimeIndex with dtype datetime64. Exactly three of the following four arguments are required to create a range:

  • start: start of the range.

  • end: end of the range (inclusive).

  • freq: step size (e.g., year, day, business day, hour, or multiples such as ‘6h’ — see list of available strings).

  • periods: number of values to generate.

print(pd.date_range(start = '2017', end = '2024', periods = 3), "\n")

print(pd.date_range(start = '2017', end = '2024', freq = 'YE'), "\n")

print(pd.date_range(end = '2024', freq = 'h', periods = 3))

Warning 32.2: pd.date_range()

The function pd.date_range() will no longer support the abbreviation ‘Y’ in the future. Instead, the abbreviations ‘YS’ (year start) or ‘YE’ (year end) can be used. Similarly, ‘M’ will be replaced by ‘MS’ (month start) or ‘ME’ (month end).

32.3 timedelta in Pandas

Time differences are created using the function pd.Timedelta(). Time differences can be created either by specifying an integer and a time unit or by using keyword arguments (valid arguments are: weeks, days, hours, minutes, seconds, milliseconds, microseconds, nanoseconds).

print(pd.Timedelta(1, 'D'))
print(pd.Timedelta(days = 1, hours = 1))
1 days 00:00:00
